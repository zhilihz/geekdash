更新日期：2026-10-20。当前能力及运行版本统一见[系统真相](../status/current-system-truth.md#1-一句话结论)。以下1054调整已随产品5b574648部署测试站点，看到旧入口时先处理未保存输入，再刷新并核版本。验证与未完成项见[本轮报告](../testing/reports/2026-10-20-local-1054-comparison.md)，本说明不表示完整阶段已验收。本地离线版单独说明，不能混用其保存方式。

### 1054调整后的常用路径

- 首页卡片可点“更新状态”，在原位置修改完整说明，再点“保存状态”。输入 `@` 可选择工程师，键盘上下键选择、回车插入；它只写入业务正文，不改变项目分工或编辑权限。简介独立显示，不能拿简要备注代替。
- 卡片按色块标题、基本资料、分工、阶段、最新说明、检查记录分组；项目日期在详情查看，阶段框显示原里程碑说明。点击卡片的普通内容即可进入详情；按钮、输入框和选择文字保持各自用途。顶部显示“今日已检查”“已X天未检查”或“尚未检查”，底部可看最近实际检查时间及检查人。
- 标签在基本信息中搜索、选择或移除，和资料、日期、分工一起点“保存基本信息”；标题不再放另一份标签编辑入口。
- 最新状态的显示日期来自每行已有保存记录；编辑框仍是人工原文，显示日期不会写回正文。详情在“最新状态说明”上方可展开“状态说明历史”读取旧正文；更新历史默认按倒序时间线阅读，想比较时再展开“查看修改前后”。
- 项目状态简要中，搜索与已选条件一直可见，完整筛选可以整体折叠；“分工人员”与“状态提及人员”分别筛选分工和正文提名，芯片与其他条件一样直接选择。导出使用当前范围内选中的正式信息，未保存输入不进入文件。

从候选中选择含空格的工程师姓名，也会保留全名用于提及人员筛选及导出；原自由提名仍保留。该链已完成本地回归并随本轮发布。暖色跨新建、详情、首页及简要已实测，其他视觉和输出限制见报告。

### 当前详情编辑与检查

具有项目编辑资格时，进入详情直接填写基本信息与分工，改完点击该区下方的“保存基本信息”。最新状态说明用于同步业务进展、问题或下一步，独立点击下方“保存状态说明”；保存任一区都不会带走或清空另一区未保存输入。系统状态和检查记录由系统显示，不需要写入状态说明。

标题右侧在今日未检查时显示“检查”；今日已检查后又有正式信息更新时显示“检查更新”。核对已保存的项目信息后点一次即可，不填写结论、备注或预览对比。成功后按钮隐藏；它不保存正在编辑的业务信息，这些输入原样保留。若结果待确认，沿原操作确认，不再次发起检查；他人先更新时保留输入，重新进入最新版后再核对。当前只记录谁在何时核对了哪个版本，不再设置每周截止或判断检查逾期。项目预计结案超期仍按项目日期显示。

项目标签已并入基本信息，输入搜索、选择和移除后随“保存基本信息”一次提交；旧版已产生的标签草稿仍可核对恢复。无编辑资格、旧版本冲突或身份失效时仍按原规则只读或冻结；默认可填写不改变这些权限。

### 当前新建与基础资料操作

新建项目沿用详情的基本信息与项目分工结构。创建人自动成为项目经理；“其他项目经理”可以输入搜索或展开多选启用账号，选错后点该人旁边的×移除。点击“保存并进入项目”后才正式创建并赋予所选人员项目编辑权限；选择列表和个人草稿本身不授予权限。所选账号已停用或不存在时，页面保留输入并要求重新选择，本次不会部分创建。

项目经理可以有多位，身份来自登录账号；硬件、软件等分工来自业务人员资料。项目经理不因此成为系统维护人。已创建项目继续在分工位置自行加入或退出，不能替别人修改经理资格；最后一位启用经理须等其他人加入后才能退出。

所有已启用且完成首次改密的业务账号、维护账号均可新增、修改、启用或停用共享基础资料，无需先负责某个项目；企业信息也按此范围维护。基础资料页只显示资料自身的信息和启用状态，不显示引用项目数量或列表。选择分类和记录后修改并点击“保存资料”；出现修改对比时核对后“确认保存”。更名保持同一资料身份，停用不会删除已有项目里的资料。已经打开的新建、详情等页面收到资料更新后会刷新候选，保留当前输入；临时读取失败可以重试。同名冲突需核对资料身份，版本冲突需保留输入后重新读取；结果未知使用“核对保存结果”或“重试原保存”。资料维护权限不授予项目编辑或账号、系统管理权限。

首页和独立检查页已更新到测试站点，详情与新建页也已接入下述分区保存。首页最初验收来源查[UI12报告](../testing/reports/2026-10-14-e04-ui12-home-checks.md)，当前状态与未测范围统一查系统真相。

在首页展开筛选后选择条件，已选项可单独取消；折叠不清空条件，搜索始终可用。顶部左侧选择项目范围，右侧选择卡片或驾驶舱；切换展示方式保留当前范围和筛选。“新建项目”位于项目列表标题行。顶部“项目检查”始终统计全部项目的今日已查与未查，不随分类或筛选缩小；点进入后默认查看全部项目中今日未查的项目，资料及最新说明只读。卡片旁可选择“通过检查”或“进入修正”。需要纠正时进入详情，明确保存后返回检查。修正信息与通过检查是两个动作，返回后仍需核对并明确通过。

通过检查后重新读取列表并同步首页当日标记。若提示结果待确认，沿原结果确认或原请求重试，不另发一次检查；无负责权限时只读。确认结果时若登录失效，原请求会保留，重新登录同一账号后继续确认。详细交互归[PRD8.12](../product/PRD.md#812-ui08全站结构与日常操作2026-10-14结构评审稿)，此处不另定检查规则。

## 当前风险编辑与纠错

风险页保留内容、高/中/低、预警中/已解除及解除说明。新增或“纠正信息”直接填写后点“保存”；人工解除填写解除说明后保存，均只提交当前风险。改错内容、等级或解除说明不用再写纠错原因，也不再加入副本后保存全项目。取消不改正式数据。

误录风险可以点“删除”，核对记录后“保存删除”；它从当前风险列表移除，原记录及修改历史保留。误点解除用“撤销误解除”，填写一次原因、核对影响后“确认并保存”。纠正解除说明保留原解除时刻，撤销误解除保留原历史。真实风险再次出现可新增，不自动改灯色、阶段、计划或检查。

无效输入保留当前表单供修正；版本冲突后复制核对并重新进入最新版。结果未知使用原保存确认或原样重试，不新增编号反复操作。其他区未保存输入保持。

## 当前检查与旧检查说明修正

- 从首页“项目检查”卡片点“通过检查”，或从详情标题点“检查”“检查更新”；记录对已保存项目的核对，不要求先保存其他区输入。浏览和普通保存不会替你检查。
- 检查记录可分批读取；在原记录点“修改说明”，直接改结论或备注并“保存说明”，不额外填原因或预览。原检查人、实际时间及核对版本保持，不新增一次检查；旧记录中原有的周/规则依据保留为历史，不再参与当前判定。
- 保存检查后共享今日已查事实；检查后项目又有正式修改，会提示“检查后有更新”，详情可再次核对。暂缓、结案项目仍可主动检查。系统不再生成周检查义务、按时/晚查或检查逾期。
- 不用初始化检查截止。旧设置页或旧标签若仍显示截止表单，刷新到当前版本；原已提交结果仍可确认，不能再保存新截止规则。
- 提交结果未知时确认或重试原操作；不要另补一条。旧版本被拒时保留输入，重新进入后核对。

## 当前结案、重开与维护

在基本信息把“项目状态”改为已结案，在同一区核对实际结案日、类型及“结案说明”，点击“保存基本信息”。正常结案且没有未完成事项时说明选填；中途结案或仍有未完成事项时，在同一说明中交代后续处理，不重复填写另一份处置说明。阶段“中途结案”定位到同一区，保留已有输入。结案不把未完成阶段改成已完成。

已结案项目可继续修改普通信息及当前结案资料；日期、类型或说明误填直接在原处改正保存。重开时选择允许恢复的原状态并保存，确认当前结案事实退出即可，不额外填重开原因；原结案历史保留。此前暂缓的项目先恢复到暂缓，需要继续时再改为恢复状态。来源不明时先核对，不能猜恢复状态。结案后维护在同一区选择开启/关闭并保存，与S7阶段分开显示。

取消本区修改恢复正式值，不清空其他区输入。无效日期或状态会指出需修正的内容；旧版本不能覆盖。结果待确认时沿原请求确认或重试；已保存而刷新失败只重新读取。结案时计划快照和原操作来源仍可从历史核对，不因普通纠错改写原审计。

## 当前暂缓与恢复

在基本信息把状态改为暂缓，填写一次暂缓原因并“保存基本信息”。暂缓保留阶段、实际日期和当前进度；可纠正信息，但推进阶段需先恢复。

恢复时在同一区选择暂缓前状态并保存，计划默认保持；若同时真实改期，在日期旁填写一次改期说明。恢复保留期间的最新信息，不自动开始阶段、顺延计划或生成检查。原状态未知会提示核对来源。

原暂缓/恢复记录的说明可直接修改并保存，不再额外填纠错原因或预览；暂缓原因不能清空。修改说明不改变项目状态。取消、无效输入、冲突及未知结果沿本区保存提示处理；不再核对所谓“本周检查影响”。

## 当前阶段卡片

阶段区沿用原版七卡片、里程碑、三线展开及工期展示。在对应卡片“开始阶段”或“里程碑完成”，核对真实日期后明确保存，完成说明选填。工期与评述点当前卡片“保存工期与评述”，不要求保存其他阶段或全项目。阶段预计完成日期由本阶段有效项目节点的最晚目标日汇总；缺日期会提示未定或未齐，纠正应回到对应项目节点。

完成只解锁下一阶段，不自动开始。S1完成后项目仍提案中；“启动项目”定位到基本信息，将状态改为进行中，核对实际启动和预计结案日期，点“保存基本信息”。S2仍须另行开始。已有日期沿用，无值时提供的日期须按实际核对；不需要先保存检查规则。真实改期填写一次说明，误填日期纠正不另填原因。

实际日期填错时在当前卡片“修改实际日期”中更正并保存，不先勾选全部阶段、不填额外原因或预览。明确改为未知只清日期，已发生的阶段状态保持。误点开始/完成走对应撤销入口；真实返工从当前已完成阶段选择回退目标，填写一次原因，最终核对受影响阶段和日期后确认保存。目标回到待开始，原历史保留。

阶段动作不顺带保存其他区输入。取消不改正式项目；校验失败保留表单，日期冲突按提示核对，系统不自动挪动其他阶段日期。旧版本被拒时复制核对并重新进入。结果待确认时用“确认原阶段结果”或“重试原阶段操作”；已保存但刷新失败只重新读取。协议见[阶段API](../specifications/api/project-actions.md)，实际验证范围见本轮报告。

## 当前日期与计划

立案、实际启动、预计结案及实际结案日期在基本信息原位修改后保存。已有计划日期改变时，在旁边选择“实际调整计划”或“纠正填错的日期”：真实改期填写一次“改期说明”，误填纠正不额外填原因或预览。计划未定时补日期不需要编造旧计划；明确清空日期沿页面“未知/未定”提示处理，普通未改字段不被清空。

需要补充计划说明时使用原说明入口保存，不会清空或顺延计划。原计划及调整历史保留；修改历史说明直接保存，不要求另外写一份纠错原因。撤销误录记录保留原历史，不能据此自动回滚后来计划；要改当前计划应在当前日期处明确处理。

实际日期纠错不自动开始或完成阶段、启动或结案；要改变状态，在本区明确选择相应状态。看板按业务日期显示剩余、今日到期、已超期或计划未定，结案结果使用结案时计划和实际结案日；周检查取消不影响这些项目日期结果。聚焦或跨日会重新读取日期结果，版本变化仍需重新进入，未保存输入保留供核对。

## 2. 服务器版预期使用流程

公网入口及已上线的最小登录、改密、负责范围和个人草稿见上文。以下保留完整业务流程，尚未开放的动作以系统真相为准；邀请码和完整账号后台仍后置。原GeekDash面板是业务迁移基底。

已开放动作使用上文的当前入口；导入、会议等后续能力仍是目标，不作为已上线操作指引。

| 场景 | 使用者操作 | 完成的标志 |
|---|---|---|
| 登录 | 用个人账号进入公网 HTTPS 站点 | 身份正确，恢复本人视图 |
| 新建 | 录入名称和已知资料，点击保存 | 项目提案中、S1 待开始；本账号负责 |
| 正式启动 | S1 完成后确认日期并保存启动项目 | 项目进行中，S2 仍需另行开始 |
| 日常更新 | 提交状态、风险或节点变化 | 显示服务端已保存，历史可查 |
| 节点完成与纠错 | 沿原节点填写真实日期并保存；前置不满足时按提示处理，实际撤销下游或解除关联时一次确认影响 | 当前完成与依赖一致，原成果及纠错历史可查；规则见SPEC-005 |
| 节点误删恢复 | 查看已删除节点，填恢复原因、核对原字段并在所属节点范围保存；旧连线供参考，需连接时明确重选 | 同一原节点恢复，历史可查，不覆盖后来关系；规则见SPEC-005 |
| 日期纠正为未知 | 在对应日期处明确改为未知并保存，不另填纠错原因或预览 | 真实动作状态及历史保持，日期待核对；规则见SPEC-003/004 |
| 需求变更纠错 | 直接修改原记录的来源、内容、接受/拒绝及决定理由，一次保存当前记录 | 原决定和当前有效结果可追溯；规则见SPEC-005 |
| 风险记录 | 新增、修改、解除或删除当前记录后明确保存；撤销误解除保留一次原因和影响确认 | 正式结果及原文/修改历史可查；规则见SPEC-005 |

| 批量导入审查 | 在独立卡片区纠正有误项、勾选正确项并保存所选审查 | 成功项入库，冲突/未选项继续待审；准确契约见 SPEC-009 |
| 调整计划 | 核对当前计划，填新日期和原因并保存 | 原始计划保留，新计划和历史可查 |
| 补充说明 | 在说明入口填写原因或措施并保存 | 当前计划保持原值，说明可查 |
| 查看超期 | 核对有效计划及系统显示的日期结果 | 沿SPEC-004统一判断，无人工超期勾选；旧人工标签已退出当前显示 |
| 完成阶段 | 核对里程碑并提交说明 | 合法推进，其他人看到新结果 |
| 暂缓/恢复 | 保存暂缓原因，恢复前复核计划 | 暂缓时停推进、可改信息；恢复此前状态 |
| 结案 | 选择类型、确认日期并说明遗留事项，点击保存 | 看板归档，保留实际阶段进度 |
| 重新打开 | 基本信息选择恢复状态并保存，确认当前结案事实退出；需要返工再选回退阶段 | 原结案历史保留，恢复此前状态 |
| 量产维护 | 在已结案项目开启维护 | 独立维护视图可跟踪，研发不被误重启 |
| 整理导出项目 | 在统一项目状态简要中按芯片等条件筛选、勾选并整理列和顺序，选择所需格式输出 | 不区分常用/芯片视图；原芯片CSV在导出选项保留，格式差异见SPEC-020，实际PDF等未验范围查系统真相 |
| 会议及固定报告（后续目标） | 按SPEC-008选择范围并生成对应产物 | 生成后可读取；不把两张原导出页等同于会议管理 |

以上生命周期前置见SPEC-003，计划与超期口径见SPEC-004。目标超期按有效结案计划和日期统一计算，人工延期功能按DEC-098取消；计划未定、今日到期及结案历史结果有各自含义，曾改期不表示当前超期。旧人工延期已退出当前显示，实际已上线范围以系统真相为准。

业务使用者各自使用独立账号，业务账号不设固定数量上限；系统另设一个专用维护管理员账号（SPEC-019）。全部项目可以查看和搜索；只有本人负责的项目可修改。负责范围设置允许自行加入/退出，需点击保存；录入新项目并保存后自动成为负责人。最后一位负责人退出前，须先由另一账号自行加入并保存。具体权限见SPEC-014。

导入审查区里的“保存待审修正”仅保存待审内容；“保存所选审查”提交通过项。待审卡片可以分次查看，尚未通过的项目不会出现在正式看板。首次入库卡片默认由上传者纠正和提交，其他人只读；处理人停用后可填写原因并保存接管，重新核对后接续，原上传者和接管历史保留；入库后保存者自动负责，其他账号可自行加入。已有项目的导入更新仍由该项目负责人处理。若提示目标项目已更新，先重新核对正式值和导入值；导入审查通过不自动新增项目检查事实。

在项目详情从基础芯片库添加或移除所选芯片，点击“保存基本信息”；选择本身不提交。统一项目状态简要按芯片整理已保存项目，不再进入独立芯片统计；业务修改仍在详情，导出准确验证范围查系统真相。所有有效启用账号均可维护基础芯片资料，项目选择仍须本人有项目编辑资格，见SPEC-006/014/020。

## 3. 判断是否真正保存

所有业务修改均点击所属范围的保存按钮，选择或输入本身不提交。“草稿已同步”表示本人底稿已存入服务器，其他人仍读正式数据；“项目已保存”才表示正式项目已提交。基本信息与项目分工共用保存，项目状态和关键日期可与本区资料同次提交；最新状态说明独立保存。风险、需求变更及客户节点保存当前记录，项目节点列表与Flow共用“保存节点与连线”；不顺带提交或清空其他区输入。阶段及检查在对应操作处保存，准确边界见SPEC-002/007。草稿、提交中和已保存分开显示；未来报告任务即使已受理，也需生成后确认能读取产物。

长文本不会因为切换页面就自动变成正式记录。进入项目后固定显示当时版本；编辑者名单实时更新，只显示人员，不显示他人的输入内容。

## 4. 常见问题的目标恢复方式

| 情况 | 应如何处理 |
|---|---|
| 他人已保存当前项目 | 按提示复制未保存文字，点击“重新进入项目”读取最新数据；旧版本不能保存 |
| 网络中断 | 保留草稿；恢复网络后检查身份和版本再提交 |
| 登录过期 | 重新登录同一账号后回到原页面；可用草稿点“继续编辑”，旧版本仅复制核对；有原结果待确认时先确认，见 SPEC-007 |
| 草稿同步超限 | 按提示处理本人旧稿，或复制/导出当前输入；正式项目尚未保存，已有服务器底稿保持，见 SPEC-007 |
| 保存校验失败 | 按字段提示修正；项目正式数据应保持原状 |
| 报告失败 | 查看任务原因和结果入口；按提示重试 |
| 基础资料已停用 | 历史仍可读，新项目选择有效资料 |
| 误删项目 | 使用回收站恢复；该能力仍为建议方案 |
| 发布新版本 | 先处理当前输入，再按提示刷新 |

## 当前节点编辑与纠错

项目节点按阶段泳道与列表查看，客户节点按日期和备注查看。负责人直接编辑名称、成果、计划日期等信息；项目节点表单点“保存节点与连线”，同时提交同一节点范围的连线和位置，客户节点点“保存客户节点”只提交当前记录。不先预览普通修改，也不再回主区保存。Flow拖动位置后仍需明确保存节点范围，其他区输入保持。

“标记完成”填写真实日期并保存；前置尚未完成时会指出阻止的节点。撤销完成、更换前置或删除关联节点影响已完成下游时，填写必要原因，核对实际受影响记录后“确认并保存”一次。取消不写正式数据，不能留下前置未完成而下游已完成的新矛盾。循环会提示具体路径，旧错误连线可明确拆除。节点目标日正常带动阶段预计日期，不增加确认步骤。

### 节点删除与恢复

在所选节点“编辑”中使用“删除这个节点”，列表与Flow使用同一入口。有旧连线时核对解除范围和必要原因，再确认保存；邻居保留，不自动桥接前后节点。无关联的误录节点不额外要求原因或影响预览。尚未保存的临时节点移除只处理副本。

在“查看/重新读取已删除节点”中选中误删记录，填写恢复原因、核对原字段并保存；需修正旧字段时在当前恢复表单明确处理。恢复沿原ID，不自动接回旧线，也不覆盖后来关系。遇实际连带影响时按表单核对一次。校验失败保留输入；旧版本或身份变化后先复制核对再重新进入。结果未知沿原编号和正文确认，不能重新生成另一笔操作。

## 当前需求变更编辑与纠错

风险页签中的需求变更保留原位置。新增时选客户/业务来源，填写内容，选择接受/拒绝并填写一次决定理由，然后保存当前记录。修改时直接改该记录，不先勾选各字段、不额外填写纠错原因，也不再预览后保存全项目。接受变更不会自动改计划、阶段、节点或灯色。

创建人、创建时间及原记录ID保留，前后决定和操作者可从项目历史查看。旧来源未知时仍显示待核对，不自动补成业务或拒绝。取消不改正式数据；字段错误保留表单；冲突或身份变化保留输入供复制，重新进入后核对。结果待确认沿原操作恢复，其他区未保存输入不随本记录提交或清空。实际版本及验收范围查[系统真相](../status/current-system-truth.md)。
