# 系统使用说明

版本：D0.15；日期：2026-09-29。服务器版尚未实现，本文明确区分当前本地版和目标操作。

## 1. 当前本地版怎样使用

原版通过本地 HTTP 服务打开 GeekDash.html。新会话选择已有 JSON 数据库、将浏览器旧数据迁移为数据库或创建空库。旧数据升级时先保存历史数据，不能直接新建空库替代。

进入管理模式并选择工程师后可以编辑。该工程师选择不是登录认证。修改后检查首页的文件保存状态；出现保存失败时保留页面和数据，重新连接文件后再保存。

详细旧版手册位于核查副本 `geekdash-system-builder/releases/GeekDash1050/docs/USER_GUIDE.md`，该目录未随文档上传。

## 2. 服务器版预期使用流程

以下是产品设计，按钮文字和入口位置将在实现时核定。

| 场景 | 使用者操作 | 完成的标志 |
|---|---|---|
| 登录 | 用个人账号进入公网 HTTPS 站点 | 身份正确，恢复本人视图 |
| 新建 | 录入名称和已知资料，点击保存 | 项目提案中、S1 待开始；本账号负责 |
| 正式启动 | S1 完成后确认日期并保存启动项目 | 项目进行中，S2 仍需另行开始 |
| 日常更新 | 提交状态、风险或节点变化 | 显示服务端已保存，历史可查 |
| 检查项目 | 主动确认检查结论 | 记录检查人、时间及结果；规则待定 |
| 调整计划 | 填新日期及原因 | 原计划保留，新计划和历史一致 |
| 完成阶段 | 核对里程碑并提交说明 | 合法推进，其他人看到新结果 |
| 暂缓/恢复 | 保存暂缓原因，恢复前复核计划 | 暂缓时停推进、可改信息；恢复此前状态 |
| 结案 | 选择类型、确认日期并说明遗留事项，点击保存 | 看板归档，保留实际阶段进度 |
| 重新打开 | 填写原因并保存，需要返工再选回退阶段 | 原结案历史保留，恢复此前状态 |
| 量产维护 | 在已结案项目开启维护 | 独立维护视图可跟踪，研发不被误重启 |
| 汇报 | 选择项目和字段，保存纪要/导出 | 得到可打开且内容正确的产物 |

以上目标操作的前置及联动统一见 SPEC-003；完整逾期判定仍待确认。

四人均使用自己的账号。全部项目可以查看和搜索；只有本人负责的项目可修改。负责范围设置允许自行加入/退出，需点击保存；录入新项目并保存后自动成为负责人。具体权限见 SPEC-014。

## 3. 判断是否真正保存

所有业务修改均点击保存，选择或输入本身不提交。草稿、提交中和已保存分开显示。“已保存”必须表示服务器已提交。看到排队中的任务只代表已受理，生成报告后还需确认能下载并打开。

长文本不会因为切换页面就自动变成正式记录。进入项目后固定显示当时版本；编辑者名单实时更新，只显示人员，不显示他人的输入内容。

## 4. 常见问题的目标恢复方式

| 情况 | 应如何处理 |
|---|---|
| 他人已保存当前项目 | 按提示复制未保存文字，点击“重新进入项目”读取最新数据；旧版本不能保存 |
| 网络中断 | 保留草稿；恢复网络后检查身份和版本再提交 |
| 登录过期 | 重新登录同一账号，恢复草稿，不自动覆盖新数据 |
| 保存校验失败 | 按字段提示修正；项目正式数据应保持原状 |
| 报告失败 | 查看任务原因和结果入口；按提示重试 |
| 基础资料已停用 | 历史仍可读，新项目选择有效资料 |
| 误删项目 | 使用回收站恢复；该能力仍为建议方案 |
| 发布新版本 | 先处理当前输入，再按提示刷新 |

## 5. 试用反馈格式

记录：环境和版本 → 哪个项目（可用脱敏编号）→ 操作步骤 → 实际结果 → 期望结果 → 是否保存/刷新后仍存在 → 出现时间。

涉及业务规则时先明确期望，避免只写“进度不对”。密码、会话令牌和真实客户敏感内容不要放进公开 GitHub Issue。

## 6. 管理员日常维护

定期检查异常项目、未完成节点、风险和计划；查看备份与任务失败；人员离开时停用账号并撤销会话。发布和数据库恢复由约定负责人按[发布维护流程](../operations/release-maintenance.md)处理。

正式域名、账号开通方式、维护时间及支持联系人尚未确定，不能把本文作为已经可访问的服务通知。
