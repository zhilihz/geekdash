- 详情重入、列表刷新或存储不可用时保留现有展示/内存输入并提示恢复；正式数据以服务器新请求为准。搜索筛选在地址、列表位置在浏览器会话、主题在本浏览器；跨设备私人状态与SSE通知尚未接入。

## 1. 当前本地版怎样使用

原版通过本地 HTTP 服务打开 GeekDash.html。新会话选择已有 JSON 数据库、将浏览器旧数据迁移为数据库或创建空库。旧数据升级时先保存历史数据，不能直接新建空库替代。

## 2. 服务器版预期使用流程

公网入口及已上线的最小登录、改密和负责范围见第0节。以下为完整业务目标，尚未开放的动作以系统真相为准；邀请码/账号后台及跨设备私人状态仍后置，后续沿SPEC-001/007接入。原GeekDash面板是业务迁移基底，已存在的页面操作逐项接入服务器保存能力。

以下是产品设计，按钮文字和入口位置将在实现时核定。

| 场景 | 使用者操作 | 完成的标志 |
|---|---|---|
| 登录 | 用个人账号进入公网 HTTPS 站点 | 身份正确，恢复本人视图 |
| 新建 | 录入名称和已知资料，点击保存 | 项目提案中、S1 待开始；本账号负责 |
| 正式启动 | S1 完成后确认日期并保存启动项目 | 项目进行中，S2 仍需另行开始 |
| 日常更新 | 提交状态、风险或节点变化 | 显示服务端已保存，历史可查 |
| 节点完成与纠错（目标，未上线） | 沿原节点录入实际完成日，核对直接前置；误填或改连线先预览并明确确认受影响节点，再保存项目 | 当前完成与依赖一致，原成果/完成及纠错历史可查；规则见SPEC-005 |
| 节点误删恢复（目标，未上线） | 查看本项目已删除节点，填原因、核对原字段；旧连线供参考，需连接时明确重选，再保存项目 | 同一原节点回到有效列表，删除/恢复历史可查；不自动覆盖后来关系，规则见SPEC-005 |
| 日期纠正为未知（目标，未上线） | 项目/阶段实际日期误填且真实日期不清楚时，选择明确未知、填原因/预览并保存 | 真实动作状态及历史保持，日期待核对；后续依赖日期时先补录，闭案不再无依据显示按期/超期，规则见SPEC-003/004 |
| 需求变更纠错（目标，未上线） | 在原客户/业务来源及接受/拒绝记录上填写原因、预览修改，统一保存项目 | 原决定和当前有效结果可追溯；规则见SPEC-005 |
| 风险记录（目标，未上线） | 新增、解除或有原因纠错先进入编辑副本，再点击保存项目 | 正式结果及原文/修改历史可查，具体规则见SPEC-005 |
| 检查项目 | 核对已保存项目、选择结论并点击保存检查；已结案可主动核对，历史结论/备注误录走明确纠错 | 保存事实及更正历史可查；准确口径见SPEC-005，本功能尚未上线 |
| 批量导入审查 | 在独立卡片区纠正有误项、勾选正确项并保存所选审查 | 成功项入库，冲突/未选项继续待审；准确契约见 SPEC-009 |
| 调整计划 | 核对当前计划，填新日期和原因并保存 | 原始计划保留，新计划和历史可查 |
| 补充说明 | 在说明入口填写原因或措施并保存 | 当前计划保持原值，说明可查 |
| 查看超期 | 核对有效计划及系统显示的日期结果 | 沿SPEC-004统一判断，无人工超期勾选；旧标签退出仍待施工 |
| 完成阶段 | 核对里程碑并提交说明 | 合法推进，其他人看到新结果 |
| 暂缓/恢复 | 保存暂缓原因，恢复前复核计划 | 暂缓时停推进、可改信息；恢复此前状态 |
| 结案 | 选择类型、确认日期并说明遗留事项，点击保存 | 看板归档，保留实际阶段进度 |
| 重新打开 | 填写原因并保存，需要返工再选回退阶段 | 原结案历史保留，恢复此前状态 |
| 量产维护 | 在已结案项目开启维护 | 独立维护视图可跟踪，研发不被误重启 |
| 汇报 | 选择项目和字段，保存纪要/导出 | 得到可打开且内容正确的产物 |

以上生命周期前置见SPEC-003，计划与超期口径见SPEC-004。目标超期按有效结案计划和日期统一计算，人工延期功能按DEC-098取消；计划未定、今日到期及结案历史结果有各自含义，曾改期不表示当前超期。当前旧标签尚未实际退出，不能把目标说明当已上线。

四位业务使用者均使用自己的账号，系统另设一个专用维护管理员账号（SPEC-019）。全部项目可以查看和搜索；只有本人负责的项目可修改。负责范围设置允许自行加入/退出，需点击保存；录入新项目并保存后自动成为负责人。最后一位负责人退出前，须先由另一账号自行加入并保存。具体权限见 SPEC-014。

导入审查区里的“保存待审修正”仅保存待审内容；“保存所选审查”提交通过项。待审卡片可以分次查看，尚未通过的项目不会出现在正式看板。首次入库卡片默认由上传者纠正和提交，其他人只读；处理人停用后可填写原因并保存接管，重新核对后接续，原上传者和接管历史保留；入库后保存者自动负责，其他账号可自行加入。已有项目的导入更新仍由该项目负责人处理。若提示目标项目已更新，先重新核对正式值和导入值；导入审查通过不自动算作本周项目检查。

在项目详情从基础芯片库添加或移除所选芯片，核对后点击“保存项目”；选择本身不提交。保存后可到芯片统计查看项目关联。芯片资料由专用维护账号维护，项目负责人修改本项目选择，见 SPEC-006/014。

## 3. 判断是否真正保存

所有业务修改均点击保存，选择或输入本身不提交。“草稿已同步”表示本人底稿已存入服务器，其他人仍读正式数据；“项目已保存”才表示正式项目已提交。普通字段/子记录统一保存项目；阶段/回退/结案等动作独立保存，先处理未存普通编辑。准确说明见 SPEC-002/007。草稿、提交中和已保存分开显示。“已保存”必须表示服务器已提交。看到排队中的任务只代表已受理，生成报告后还需确认能下载并打开。

长文本不会因为切换页面就自动变成正式记录。进入项目后固定显示当时版本；编辑者名单实时更新，只显示人员，不显示他人的输入内容。

## 4. 常见问题的目标恢复方式

| 情况 | 应如何处理 |
|---|---|
| 他人已保存当前项目 | 按提示复制未保存文字，点击“重新进入项目”读取最新数据；旧版本不能保存 |
| 网络中断 | 保留草稿；恢复网络后检查身份和版本再提交 |
| 登录过期 | 重新登录同一账号，选择本人草稿；同版本恢复编辑，旧版本供复制核对，见 SPEC-007 |
| 草稿同步超限 | 按提示处理本人旧稿，或复制/导出当前输入；正式项目尚未保存，已有服务器底稿保持，见 SPEC-007 |
| 保存校验失败 | 按字段提示修正；项目正式数据应保持原状 |
| 报告失败 | 查看任务原因和结果入口；按提示重试 |
| 基础资料已停用 | 历史仍可读，新项目选择有效资料 |
| 误删项目 | 使用回收站恢复；该能力仍为建议方案 |
| 发布新版本 | 先处理当前输入，再按提示刷新 |

## 6. 管理员日常维护

定期检查异常项目、未完成节点、风险和计划；查看备份与任务失败；人员离开时先按 SPEC-001 完成项目交接，再由指定维护人员保存停用并撤销会话。共享资料、公共业务设置和账号启用/停用、维护账号换任由唯一维护管理员管理；未完成导入批次按 SPEC-009 明确保存接管，不能自动通过。项目交接包括结案项目，须先有其他启用负责人加入并保存。资料改名先核对引用影响，已引用资料仅停用；检查截止只选每周星期几，保存后立即应用本周并沿用到以后每周；截止日全天可检查，次日起才算逾期；本周已检查仍保留，按时/晚查使用新截止，见 SPEC-005/019。测试首版发布采用检查通过后人工择时安排，发布前处理未保存输入；完整备份和恢复按已确认策略维护。具体运维操作者和存放位置仍需落实。发布和数据库恢复由约定负责人按[发布维护流程](../operations/release-maintenance.md)处理。
