## 当前结案、重开与维护（E04-B06）

基本信息中的“结案项目”填写实际结案日、类型和说明；仍有未完成事项时填写处置说明。原阶段“中途结案”打开同一表单并预填终止，可核对后更改。预览遗留事项、日期结果及实际进度，点击明确保存；不会因为结案把七卡片改成已完成。

已结案项目可以继续保存普通信息。“重新打开项目”核对将恢复的原状态并填原因，预览保存；原状态为暂缓时先回暂缓，之后需要继续再点恢复。来源不明时先核对，不猜恢复状态。开启/结束维护单独明确保存，维护标识与S7分别展示。

“纠正当前结案”勾选具体字段，填写原因，预览原/新值后保存；明确未知的结案日期或计划分别勾选对应选项，未选字段保持。结案时计划快照的纠正不会修改当前计划；原结案人、时间和原文从修改历史查看。旧版本及旧结案周期均不能覆盖当前事实。

操作前处理未保存普通编辑；取消恢复普通输入，预览后改输入须重新预览。结果待确认时沿原正文/编号确认或重试；已保存而刷新失败只重读。准确范围归[结案报告](../testing/reports/2026-10-10-project-close.md)，行为归SPEC-003/004/005；原生表单实点仍待B09。

## 当前暂缓与恢复（E04-B05）

详情基本信息中的“暂缓项目”填写原因，预览状态/本周检查影响后点击保存。暂缓保留原阶段卡片和实际日期，阶段显示“暂缓保留”；此时可保存普通文字、计划和事实纠错，推进阶段需先恢复。

“恢复项目”展示暂缓前状态及当前最新计划。默认保持计划，如需同时改计划则勾选、填写日期和必要的调整原因，再预览保存。恢复保留暂缓期间最新数据；不自动开阶段、顺延计划或生成检查。原状态未知会提示核对来源。

原暂缓/恢复记录可查看原文及更正来源；“纠正说明”填写更正文字和原因，预览再保存。恢复说明可明确清空，暂缓原因不可空。修改说明只纠正文字，不恢复或暂缓项目。

看板和详情显示本周待查/检查逾期等服务器结果；暂缓不在默认必查范围，恢复进行中立即应用原首次应检依据和本周规则。首次义务未知/未到分别提示，不伪造检查。B07已接入“保存检查”，入口见上文当前检查章节。旧版本、网络结果未知、取消恢复和复制沿原动作恢复入口；页面实点验收仍待B09，准确范围见[暂缓报告](../testing/reports/2026-10-10-project-pause.md)。

## 当前阶段卡片（E04-B01～B03，本地及公网已部署）

阶段区沿用原版七卡片、里程碑、三线展开及工期展示。负责人点击卡片“开始阶段”，核对实际开始日后点“保存开始”；进行中卡片点“里程碑完成”，核对实际完成日、选填说明后点“保存完成”。取消只保留本标签副本，不修改正式项目。工期/评述修改后与普通内容统一“保存项目”；中途结案见下方结案入口，预填终止供人工核对。

完成只解锁下一阶段，不自动开始。S1完成后项目仍提案中，在阶段区“启动项目”核对实际启动日、预计结案日及首次应检预览，点击“保存启动项目”后总体进行中，S2仍须另行开始。当前已存计划可保留；本次改变既有计划须填写改期原因。维护账号须先在设置明确保存初始检查截止星期，业务账号只读；未知原始计划不补造。进度由正式完成事实读取。动作前有普通编辑，先明确保存、放弃或继续编辑；错误时原输入保留。旧版本被拒时复制核对并重新进入，过期副本不可直接提交。

实际日期填错时进入“纠正实际日期”，勾选具体字段、填写原因，再预览并明确保存；所选日期留空表示明确未知，已发生的阶段状态保持。未勾选字段保持原值。误点开始/完成用卡片对应撤销入口；实际返工用已完成卡片的回退入口，预览目标及后续影响后保存，目标回到待开始，原历史保留。

打开动作前先处理普通编辑；动作表单期间普通输入暂停，取消恢复。预览后再改输入必须重新预览；取消不写正式项目，旧版本冲突保留原因供复制。若提示结果待确认，用“确认原阶段结果”或“重试原阶段操作”；若已保存而刷新失败，只需重新进入查看。当前可用范围以[系统真相36](../status/current-system-truth.md#36-e04-b03阶段纠错与回退2026-10-10固定部署)及实际部署记录为准，准确协议见[阶段API](../specifications/api/project-actions.md)。

## 1. 当前本地版怎样使用

原版通过本地 HTTP 服务打开 GeekDash.html。新会话选择已有 JSON 数据库、将浏览器旧数据迁移为数据库或创建空库。旧数据升级时先保存历史数据，不能直接新建空库替代。

在项目详情从基础芯片库添加或移除所选芯片，核对后点击“保存项目”；选择本身不提交。保存后可到芯片统计查看项目关联。芯片资料由专用维护账号维护，项目负责人修改本项目选择，见 SPEC-006/014。

## 3. 判断是否真正保存

所有业务修改均点击保存，选择或输入本身不提交。“草稿已同步”表示本人底稿已存入服务器，其他人仍读正式数据；“项目已保存”才表示正式项目已提交。普通字段/子记录统一保存项目；阶段/回退/结案等动作独立保存，先处理未存普通编辑。准确说明见 SPEC-002/007。草稿、提交中和已保存分开显示。“已保存”必须表示服务器已提交。看到排队中的任务只代表已受理，生成报告后还需确认能下载并打开。

长文本不会因为切换页面就自动变成正式记录。进入项目后固定显示当时版本；编辑者名单实时更新，只显示人员，不显示他人的输入内容。

## 4. 常见问题的目标恢复方式

| 情况 | 应如何处理 |
|---|---|
| 他人已保存当前项目 | 按提示复制未保存文字，点击“重新进入项目”读取最新数据；旧版本不能保存 |
| 网络中断 | 保留草稿；恢复网络后检查身份和版本再提交 |
| 登录过期 | 重新登录同一账号，选择本人草稿；同版本恢复编辑，旧版本供复制核对，见 SPEC-007 |
| 草稿同步超限 | 按提示处理本人旧稿，或复制/导出当前输入；正式项目尚未保存，已有服务器底稿保持，见 SPEC-007 |
| 保存校验失败 | 按字段提示修正；项目正式数据应保持原状 |
| 报告失败 | 查看任务原因和结果入口；按提示重试 |
| 基础资料已停用 | 历史仍可读，新项目选择有效资料 |
| 误删项目 | 使用回收站恢复；该能力仍为建议方案 |
| 发布新版本 | 先处理当前输入，再按提示刷新 |

## 节点副本与明确纠错（E04-B08已部署，原生页面待验）

### 节点删除与恢复（D/E已部署，原生页面待验）
