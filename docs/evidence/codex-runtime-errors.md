### PE-20261010-006 风险快照全审计扫描

- 实际原因：WHERE id IN (SELECT MIN(id) ... UNION ALL SELECT MAX(id) ...)被MySQL转成dependent、cacheable=false子查询，外层audit_log ALL、估算每次2431行；目标实体子查询虽有range索引，仍被重复执行。
- 修复：同一读取先派生有限目标ID，再JOIN audit_log主键；实体索引range、派生dependent=false、外层a为PRIMARY/eq_ref且每目标1行。没有新增表/索引/Redis，创建/解除原快照契约保持。
- 复测：真实风险五组120请求通过；同规模四会话640测量请求零错误，详情/风险预览/风险保存P95=40/30/65ms，工具256MiB/V8旧堆96MiB，结束RSS约222MiB。这是环回数据，固定云验及页面验收另归报告。
- 证据：[修正前计划](2026-10-10-project-risks-capacity-before-sql.json)、[修正后计划及测量](2026-10-10-project-risks-capacity-check.json)；[复盘](#pe-20261010-006-复盘)。保留原方案测量，不用反复重试覆盖慢结果。
