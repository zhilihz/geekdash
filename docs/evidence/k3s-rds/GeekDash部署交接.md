# GeekDash：阿里云K3s + RDS部署说明

2026-10-29 · 已确认前后端独立K3s部署，详细方案讨论中，未实施。本文是[运维方案](../../operations/release-maintenance.md#k3s-production-delivery)的转发简版；完整施工思路见[执行计划1.4](../../implementation/execution-plan.md#k3s-delivery-plan)。

```text
同一HTTPS域名 → 页面/资源 → 前端Service → 前端Deployment
             └→ /api    → 后端Service → 后端Deployment → RDS MySQL
                                             └→ 原文件持久卷
后端镜像另用于一次性迁移/初始化Job → RDS MySQL
```

- **数据库：**阿里云RDS MySQL 8.0+（8.0及以上，不限定8.0.x），按实际部署版本验证兼容性；部署前核对内网连通和白名单，地域现在不用单独提供。
- **首次数据：**已确定使用本项目空白新库，创建结构并初始化管理员；项目和基础资料之后由用户经备份导入。初始化发现非预期已有数据时停止，不清库、不自动迁移旧环境；后续升级不重置管理员。
- **交付物：**两份配对镜像及digest、K3s资源清单和环境配置、发行记录；迁移Job复用后端镜像。当前带MySQL的Compose包不适用，桌面安装包/本地数据库/开发资料不进新镜像。
- **运行：**复用实际集群入口，同域支持32MiB上传及SSE；运行账号与迁移账号分离。已确认首版后端单副本与维护窗口发布，具体时段/时长待定；不将K3s等同多副本高可用。
- **存储：**数据库放RDS，导入原文件仍需持久存储并单独备份。
- **域名：**用户之后提供，按部署配置注入，不写入镜像；不默认更改旧腾讯云入口。域名和证书到位后完成正式HTTPS及登录验证。

部署前请同事确认RDS精确版本、库是否为空、内网地址/库名/授权/CA，以及K3s版本、入口、存储、节点架构、Harbor节点拉取及日志备份设施。具体维护安排、文件存储和恢复目标需收口；密码通过受控方式提供，不写进此文档。不默认集群使用Nginx或Traefik，也不默认PVC可跨节点迁移。应用改造、K3s清单、迁移/发布入口及技术验证由开发侧交付，不能以旧镜像交给同事替代改造。
