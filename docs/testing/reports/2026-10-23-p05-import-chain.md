## 7. 用户实际操作暴露的未完成链路

用户反馈“按自己的操作同步不到看板，点击位置太多且冲突”。随后只读查询和代码核查发现：

| 位置 | 已观察事实 | 结论与限制 |
|---|---|---|
| 整批结果 | 真实批3有35项目，其中2已正式采用、33待处理；另有51条基础资料采用 | 整份导入未完成，资料保存数量不能充当项目入库数量 |
| 看板读取 | `view=all`页面已显示正式项目32、33 | 这两个项目可用，不能据此推导余下项目已导入 |
| 批量实现 | `saveSelected`先执行`prepareCatalogs`，再逐项目预览、采用；这些循环均在浏览器 | 后台没有接收并持续完成整个已提交批次，切页会终止前端后续调度 |
| 单项反馈 | 项205采用请求服务端200，浏览器仍保存待确认操作，记录中没有紧随其后的单项回读 | 已保存与页面反馈脱节；具体由导航还是传输导致，尚不能定论 |
| 恢复范围 | 同账号状态中批4与批3项205待确认并存，初始化仅恢复当前批次条目 | 跨批次/标签恢复存在遗漏风险，不能通过清空页面状态掩盖 |
| 验收隔离 | 自动化创建的页面出现其他导航，本轮合成文件读取状态与实际批次状态共存 | 未确认操作者；后续不得继续把该页当专用测试页，更不能让自动化干扰用户判断 |

诊断材料位于忽略的`test-results/p05-user-path-read-output-private.txt`及浏览器只读观察，真实名称和文件正文不纳入Git。计数只代表该次快照。
