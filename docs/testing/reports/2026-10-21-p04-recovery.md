- 清理：脚本正常退出，仅按本次记录的账号/项目 ID 清理合成夹具；无全表清空或迁移。

## 3. 本轮必要修正

1. `PersonalDrafts` 记录本次本机写入是否成功；失败后不再被“输入已留在本机”覆盖。离开页面用实际本机保护结果决定提示。
2. 详情旧稿读取、新建旧稿读取、退出缓存访问的异常在所属入口处理，存储禁用不会阻断正常工作。新建已确认成功后，缓存清理失败不改写成功结果。
3. 草稿端点收到 HTTP 413 时按“草稿过大”展示；正文在进入业务处理前被拒绝，也能说明真实原因，没有调大容量限制。

## 4. 复验入口与限制

在确认独立实例 UUID 后使用现有忽略的 `test-results/p04-probe.ps1` 运行：

```powershell
./test-results/p04-probe.ps1 node --max-old-space-size=256 scripts/verify-scoped-ui.mjs --recovery
./test-results/p04-probe.ps1 npm run check
```

该模式只运行本报告的 7 组，默认完整页面验证模式保持。测试页清理先停止其身份相关工作、等待已有请求结束，再销毁执行环境；不可将销毁后异步回调访问空 document 的测试错误算作产品错误。

本报告不宣称完成全部 P04、全页面视觉、原生关闭恢复或公网验收。最终构建、原生补验、合并和部署由阶段主任务统一记录。

## 5. 原生验收发现的节点字段定位问题

主任务原生新增项目节点时漏填输出成果，服务端拒绝正确，但页面只有“请修正标出的字段。请填写有效文字”，没有指出字段。本轮复用既有节点字段名称，将 `nodeOps.N.output` 等错误路径显示成“输出成果：请填写有效文字”，聚焦并标记原输入；输入后清除该字段错误标识。预览与正式保存拒绝使用同一映射，不新增校验要求、字段或表单。

`verify-scoped-ui.mjs --node-errors` 3 组、30 次真实 HTTP 通过：[结果](../../evidence/2026-10-21-p04-recovery/scoped-ui-node-errors.json)。仍使用上述隔离实例，结果中的“线上提交包”指脚本临时 HTTP 服务的传输层，没有操作公网数据。

| 实际路径 | 结果 |
| --- | --- |
| 项目节点填名称但漏成果 → 原预览拒绝 → 补成果保存 | 正确显示输出成果字段，焦点和 `aria-invalid` 指向原输入；名称保留、数据库不写；补填后新 GET/SQL 为同一节点，版本和历史只增加一次。 |
| 预览通过 → 传输层故意清空成果 → 真实 PATCH 拒绝 → 核对原表单再保存 | 拒绝后原名称/成果输入仍在，回到成果字段；没有部分写入，纠正重存后只增加一版和一条历史。 |
| 客户节点填备注但漏名称 → 预览拒绝 → 补名称保存 | 错误明确为节点名称，备注不丢失；补名称后同处保存，新 GET/SQL 确认。 |

此项代码后再次执行 `npm run check` 通过。原生复验和最终构建由主任务接续，不以执行模型断言代替最终页面验收。

## 8. 多处变化的因果预览与草稿入口归位

按用户 2026-10-21 补充，既有影响预览在原前后表格上方说明起因、直接变化与下游缘由，体验归 [PRD 8.8](../../product/PRD.md#88-前后对比表格dec-112)。阶段取实际服务器预览；节点影响目标只取服务器要求同时撤销完成的 ID，依赖路径取实际候选连线。对于未确认时尚未清空的下游完成日期，预览显示本次确认后将得到的前后值，不把它当作已经写入。不同节点上的独立操作并列；同节点多项操作保留每个起因，不以同键覆盖其中一个。

基本区重新打开已结案项目在原有一次确认内复用现有结案预览接口，说明当前结案事实及维护标记的变化；其他独立字段继续作为本次基本区输入，不伪装成重开的自动结果。普通文字和单一日期纠正不增加预览或确认；SPEC 业务规则没有改动。
