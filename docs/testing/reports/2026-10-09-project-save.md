## 2. 真实保存链路

npm run test:saves 实际使用 MySQL test_app/test_migrator、真实 HTTP 和新连接，8 组通过：

- 四字段同事务、版本加一、审计只记实际差异、回执固定本次结果；大整数 ID/version 使用字符串。
- 同编号并发重试只发生一次有效修改；字段顺序不影响摘要，不同内容复用编号拒绝。
- 同版本只有一个提交成功；旧版本不覆盖；无变化仅留回执、不增加版本或历史；旧回执返回原结果。
- 四项白名单、business 项目只读、null/类型/名称/UTF-8 字节及无效 Unicode 拒绝，不截断输入。
- 真实审计或回执 SQL 故障整事务回滚；真实 COMMIT 完成但应答丢失返回未知，原请求只读对账可恢复成功。
- 在途对账未查到不误报失败；重启进程后回执可重放；池耗尽与新请求恢复通过。
- 同项目四并发、5 轮20 请求，每轮一成功三冲突；时间见脱敏证据。
- 默认历史20、单次最多100；101 拒绝；515 条历史可全部续页、无重复，旧历史单独保留。EXPLAIN 允许项目索引并选择 PRIMARY range；不虚报必须使用某索引。

证据：[保存检查](../../evidence/2026-10-09-project-saves-check.json)。项目读取、固定快照及真实就绪回归通过；构建类型检查、静态资源/真实 HTTP、失败候选保留和 npm test 通过。

## 5. 错误与可复用处理

按 codex-error-log 的项目范围判断，将本次特有修复留在本报告，遵守本项目 docs 分类；入口→快速处理→复盘如下。

| 入口 | 快速处理卡 | 验证入口 |
|---|---|---|
| GD-SAVE-001 历史续页重复 | ORDER BY 用 audit_log.id 数字列，不用 CAST(id AS CHAR) 的同名别名 | test:saves 超过500条续页断言 |
| GD-SAVE-002 不同项目并发死锁 | 写事务 READ COMMITTED，保留项目 FOR UPDATE、版本与回执唯一键；读快照保持原隔离级别 | test:capacity 4并发不同项目 + test:saves 同项目竞争 |

GD-SAVE-001：原排序意外匹配字符串投影别名，数字顺序和 id 游标不一致；改为限定原列后真实515条历史无重复。不能靠客户端去重隐藏漏页。
