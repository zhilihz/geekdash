## 5. 统一字体、按钮和必要表单

用户本轮要求全站统一风格，并将必要表单按信息关系组织。沿用既有三主题与页面结构；没有新增输入字段、必填条件、原因、审查步骤或保存范围。

| 项目 | 本轮采用值 | 落点 |
| --- | --- | --- |
| 字体 | `Noto Sans SC → Microsoft YaHei UI → Microsoft YaHei → PingFang SC → sans-serif` | `read.css` 为共享入口；原两份页面字体声明移除，控件继承字体 |
| 正文与辅助信息 | 正文14px；标签/操作13px；日期等辅助信息保留12px | 保留原版紧凑信息密度，取消浏览器控件自带字体 |
| 标题 | 页面标题26px、详情标题22px、分区18px、卡片16px | 沿用现有语义层级；手机标题按已有响应式规则缩小 |
| 普通按钮 | 36px起、文字13px/20px行高、圆角6px、描边 | 返回、取消、普通操作共用共享样式 |
| 主要按钮 | 40px起，使用当前主题 `accent-dim` | 保存、新增节点、通过检查；暖色选中态不再硬编码紫色 |
| 紧凑操作/危险/禁用 | 记录内操作约30～32px；删除用危险色描边；禁用透明度0.5 | 保留表格密度；修改与解除不再共用删除的红色；现有禁用逻辑不变 |
| 表单结构 | 标题 → 当前记录字段 → 已有影响信息 → 保存/取消 | 标签在上、输入在下；相关日期两列，长文本整行；手机一列 |
| 因果信息 | 起因 → 直接变化 → 真实依赖带来的后续变化 | `.impact-chain` 用嵌套层级和左侧细线；仍保留本次实际变化前后表格 |

风险、需求变更各有标题、说明与分隔；编辑表单位于对应板块内。节点表单把名称/成果作为整行，阶段/目标日期并列，已有动作集中在底部。所有调整只组织原有字段。

Figma 原有组件 `2:105`、`2:107`、`2:109` 已原位改为40/36/36px高、13px文字、6px圆角，仍使用原颜色变量和字体。W08既有节点影响提示补上前置关系的因果说明；W10既有删除提示说明当前列表变化和阶段不受影响。保留原型默认变量状态，没有新增页面或流程。见[同步回读](../../evidence/2026-10-21-p04-design-alignment/style-causal-sync.json)、[W08预览](../../evidence/2026-10-21-p04-design-alignment/W08-causal-preview.png)、[W10预览](../../evidence/2026-10-21-p04-design-alignment/W10-causal-preview.png)。两张预览截图来自临时打开原有影响状态，采集后已恢复默认变量；不是永久展开的新表单。
