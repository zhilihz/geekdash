# 测试与验收策略

版本：D0.22；日期：2026-09-30。此文为目标测试设计；下表未执行的场景不能宣称通过。待决业务规则的候选场景须在规格确认后更新预期，不能据测试表反向批准业务规则。

## 1. 已有测试的边界

已有测试和本轮实际执行范围统一见[系统真相第 5 节](../status/current-system-truth.md#5-本轮实际验证)，原始结果见 [evidence](../evidence/2026-09-29-source-diagnostics.json)。局部模拟或历史通过记录不能证明服务器版业务正确。

## 2. 测试层次

1. 规则测试：用少量有代表性的输入和边界案例验证公开规则，日期使用可控业务时钟。
2. 模块集成测试：真实 MySQL、真实迁移，通过模块接口验证业务和事务；这是核心投入。
3. 端到端测试：实际登录和页面操作，只覆盖重要链路及关键展示，避免大量脆弱 DOM 快照。
4. 运行与升级演练：重启、迁移、备份恢复、任务恢复和真实网络性能。

不要为了覆盖率写“实现做了什么就断言做了什么”的镜像测试。小而纯的日期规则单元测试仍有价值；测试深度取决于风险和结果，不取决于文件数。

### 本轮确认后的验证补充

TEST-015/028 按 DEC-034/035/036 补充验证：首次入库项目与提交者负责关系同事务；未知原创建人仍未知，旧业务人员不会获得账号权限。默认非上传者可读首次入库待审项，但 UI 和直接写请求均不能修正/提交；已明确保存接管的当前处理人按 DEC-039 接续资格验证；已有项目更新只按当前负责关系，不因上传身份获得权限。卡片与项目双版本过期均拒绝，重复/并发入库不重复新增。

最后负责人退出被拒时关系/版本/业务审计不变；另一个账号主动加入并保存后原负责人可退出，退出后只读且新请求回读正确。两位负责人并发退出不得留下零负责人；加入/退出失败整体回滚，成功关系及审计可回读；项目生命周期、进度、计划和检查记录保持原规则。上述为验收设计，尚未执行。

## 4. 数据与环境隔离

- 自动测试使用专用数据库和账号；共享人工试用数据库不作为测试清理目标。
- 执行破坏性清理前检查数据库身份、环境标识及测试数据归属，不能只看连接是否成功。
- 迁移演练使用脱敏副本；不得把真实客户、密码、会话、服务器私有信息写进公开夹具或报告。
- 本地存储模拟仅用于验证前端局部逻辑，不能代替数据库事务和认证测试。
- 共享服务器压测先限制规模与时段，监测其他业务；本轮未授权关闭其他业务。

## 5. 每次变更的检查范围

规则修复：先建立失败输入，再验证修复及相关模块。跨模块、数据库、认证或发布变动扩大到核心端到端与迁移检查。文档编辑只验证链接、结构和一致性，不运行无关应用测试。

上线候选必须覆盖认证、真实写入回读、并发、主要报告、部署版本与备份状态。测试完成后没有新的代码变动或疑点，不重复无意义全量运行。

## 6. 验收记录格式

记录：需求/规格编号、构建版本、数据库版本、数据来源、环境、操作步骤、预期、实际、持久化回读、下游消费、异常恢复、执行时间和执行人。失败必须指出恢复入口或明确下一步，不能只留下“失败”。
