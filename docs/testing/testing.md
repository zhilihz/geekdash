# 测试与验收策略

版本：D0.56；日期：2026-10-08。此文为目标测试设计；本轮补 TEST-037 当前四项保存的验收设计，尚未执行。代决采用的行为按 SPEC-002，测试不能冒充功能实现或用户逐项回答。

## 1. 已有测试的边界

已有测试和当前实际执行范围统一见[系统真相](../status/current-system-truth.md)，旧版函数核查见其第 5 节，原始结果见 [evidence](../evidence/2026-09-29-source-diagnostics.json)。局部模拟或历史通过记录不能证明服务器版业务正确。

当前按 DEC-071 先验收免登录工程基底；身份、注册、账号管理及依赖可信身份的场景保留为后续测试目标，不列为本次部署前置，也不标为已通过。

## 2. 测试层次

项目只读首批另记 TEST-036：真实测试库输入 → 列表筛选/分页 → 完整详情 → 并发提交期间一致性读取 → 新请求读取新版；包含 bigint、非法输入、无写接口、池耗尽恢复和浏览器返回状态。执行入口 `npm run test:projects`，实际结果与未覆盖范围见 [E03 报告](reports/2026-10-08-project-reads.md)。与会改变测试库结构的就绪/迁移故障测试顺序执行，浏览器夹具清理后再执行要求空库的回归，不并行混用。

1. 规则测试：用少量有代表性的输入和边界案例验证公开规则，日期使用可控业务时钟。
2. 模块集成测试：真实 MySQL、真实迁移，通过模块接口验证业务和事务；这是核心投入。
3. 端到端测试：实际登录和页面操作，只覆盖重要链路及关键展示，避免大量脆弱 DOM 快照。
4. 运行与升级演练：重启、迁移、备份恢复、任务恢复和真实网络性能。

不要为了覆盖率写“实现做了什么就断言做了什么”的镜像测试。小而纯的日期规则单元测试仍有价值；测试深度取决于风险和结果，不取决于文件数。

## 4. 数据与环境隔离

- 自动测试使用专用数据库和账号；共享人工试用数据库不作为测试清理目标。
- 执行破坏性清理前检查数据库身份、环境标识及测试数据归属，不能只看连接是否成功。
- 迁移演练使用脱敏副本；不得把真实客户、密码、会话、服务器私有信息写进公开夹具或报告。
- 本地存储模拟仅用于验证前端局部逻辑，不能代替数据库事务和认证测试。
