版本：D0.63；日期：2026-10-22。此文维护验收场景与证据要求；P05已实施并完成部分本地验证，实际通过/未测范围见[P05报告](reports/2026-10-22-p05-imports.md)。页面验收仍进行中，部署尚未执行；公司网络与实际多人使用不因本地合成验证而通过。行为以SPEC为准，测试不能代替业务决策。

2026-10-20：DEC-132/133改变资料权限与检查规则，TEST-027/029已更新目标，未执行新测试；下方历史UI/周规则用例只作来源，冲突时以当前SPEC为准。Q-032候选未确认为测试预期。

## 1. 已有测试的边界

已有测试和当前实际执行范围统一见[系统真相](../status/current-system-truth.md)，旧版函数核查见其第 5 节，原始结果见 [evidence](../evidence/2026-09-29-source-diagnostics.json)。局部模拟或历史通过记录不能证明服务器版业务正确。

最小身份与完整项目主干沿DEC-090的已有报告保留；注册和完整账号维护仍为后续目标。当前P05的实现与执行结果见[P05报告](reports/2026-10-22-p05-imports.md)。其他历史设计中的“未执行”须结合对应报告日期读取，不把部分实际通过扩展为全部目标通过。

账号数量和并发范围引用SPEC-001/012及DEC-122；验收不得以固定人数作为并发目标、基准或上限，并发档位待按实际使用规模确定。测试记录当次账号数、独立会话数和负载；不据账号无固定数量上限宣称无限并发性能。性能优化按DEC-111后置，先完成核心功能及必要的并发正确性验证。历史报告的实际测试数量和首批账号标识保留用于追溯，不作为当前规模要求。

## 2. 测试层次

项目只读首批另记 TEST-036：真实测试库输入 → 列表筛选/分页 → 完整详情 → 并发提交期间一致性读取 → 新请求读取新版；包含 bigint、非法输入、无写接口、池耗尽恢复和浏览器返回状态。执行入口 `npm run test:projects`，实际结果与未覆盖范围见 [E03 报告](reports/2026-10-08-project-reads.md)。与会改变测试库结构的就绪/迁移故障测试顺序执行，浏览器夹具清理后再执行要求空库的回归，不并行混用。

1. 规则测试：用少量有代表性的输入和边界案例验证公开规则，日期使用可控业务时钟。
2. 模块集成测试：真实 MySQL、真实迁移，通过模块接口验证业务和事务；这是核心投入。
3. 端到端测试：实际登录和页面操作，只覆盖重要链路及关键展示，避免大量脆弱 DOM 快照。
4. 运行与升级演练：重启、迁移、备份恢复、任务恢复和真实网络性能。

不要为了覆盖率写“实现做了什么就断言做了什么”的镜像测试。小而纯的日期规则单元测试仍有价值；测试深度取决于风险和结果，不取决于文件数。

### 按PRD行为结果验收（DEC-128）

对照[PRD第9节](../product/PRD.md#9-逐行为结果与恢复清单)和9.22对应表，在所属任务报告记录“PRD章节/行为行→初始事实与输入→实际操作→预期及实际→独立SQL/新请求/页面或文件证据→通过/失败/未测/不适用”。不适用写明依据；读取没有写入不是漏测事务，未执行的异常也不能计为通过。

- 成功/无变化：真实请求后核对正式字段、版本、关联、审计与回执，随后新请求及对应页面消费；无变化不伪造历史。
- 取消/校验或前置拒绝：验证正式状态保持、其他范围未被带入、输入仍能修正继续；不是只断言错误文本。
- 并发/失权：真实不同账号或同账号独立标签竞争，核对拒绝方无覆盖、本人输入保留及新资格来源。账号数量不因用例样本变成产品上限。
- 已回滚/提交未知：对真实事务的关键写点注入故障，及COMMIT后丢响应/进程恢复；独立连接判明事实，再走原操作查询/重试，证明没有重复项目、检查或历史。
- 读取/下游失败：保存成功但新读失败时页面仍知道已保存，恢复读取不触发重复业务；部分历史失败不假装没有历史。
- 草稿/偏好/通知：覆盖迟到、旧基线、失权、跨设备及断流，核对正式数据与个人内容的边界；通知或本机存储失败不能伪报业务保存失败。
- 实际前端：代表性正常、字段拒绝、冲突、结果未知及恢复路径通过真实浏览器核查，长文/完整关联及返回位置目视；模拟DOM/API成功不能替代这些体验证据。

相同机制可用一个贯通的故障场景引用到多个适用PRD行，专有前置仍各自覆盖。脚本断言须针对结果和真实状态，不为每个按钮/内部函数堆独立浅测试。发现现有错误分支没有产品反馈或PRD未列结果，先补PRD及必要SPEC，再改实现和对应验收；本节本身不是测试执行记录。
