## 3. 已有能力与边界

| 维度 | 事实 |
|---|---|
| 技术结构 | 六个原生 HTML 页面 + 一个共享 projects-data.js，无服务端应用 |
| 业务页面 | 主看板、项目详情、基础资料、设置、状态纪要、芯片统计 |
| 项目状态 | 提案中、进行中、暂缓、已结案；量产维护是已结案附加标识 |
| 阶段 | 七阶段，含需求立项、预启动、PEVT、EVT、DVT、PVT、MP |
| 正式存储 | 用户选择的 JSON 文件，通过 File System Access API 自动写回 |
| 页面共享 | localStorage 为缓存，sessionStorage 保存会话与返回上下文，IndexedDB 保存文件句柄 |
| 身份 | 浏览/管理模式及可选工程师，不构成身份认证 |
| 历史 | 浏览器产生的状态与操作文字，不具备可信服务端操作者及事务审计 |
| 数据关系 | 人员、芯片等大量按名称引用，ID 由浏览器集合计算 |
| 备份与输出 | JSON、Markdown、CSV、PDF 等；会议运行态未纳入完整业务备份 |

### 当前业务行为，不等于已认可的未来规则

| 链路 | 代码中的当前行为 | 仍需讨论的含义 |
|---|---|---|
| 看板分类 | 提案与暂缓合并视图；进行中；普通已结案；量产维护 | 是否保留现有分类和统计口径 |
| 阶段推进 | 页面按首个未完成阶段提供操作；S1 完成时提案可自动变进行中 | 启动条件、跳过、回退和异常导入如何处理 |
| 进度 | 已完成阶段数量映射到固定百分比 | 该百分比是否代表可接受的业务进度估算 |
| 延期 | 当前延期主要读取人工标记；历史延期由另一个判断统计 | 日期逾期、历史改期和人工风险如何分别展示 |
| 结案 | 普通表单可改状态，中途结案也进入已结案 | 正常交付和中途终止是否必须独立统计 |
| 检查 | 管理模式打开详情会更新 lastCheckAt | 看过是否能代表完成检查 |
| 保存 | 修改浏览器对象后写回整个项目集合，再防抖回写文件 | 四人共享写入必须重新设计事务与冲突处理 |
