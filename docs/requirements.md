# 需求清单

版本：D0.1；日期：2026-09-29。本文登记目标，不宣称服务器版已实现。

## 来源

- U1：用户提供 AIGeekDashCX.zip，要求找最新版本，讨论四人使用、速度、身份验证、状态记录、常驻 MySQL 和服务器架构。
- U2：用户明确四人均为管理员，权限相同；状态包括登录、页面筛选和位置、项目进度、修改历史。
- U3：用户指定使用 tccli 可访问的新加坡服务器测试；后续明确测试先走公网。
- U4：用户要求讨论 Redis 排队、判定和运行问题、深模块、有效测试、长期维护、更新推送时机和系统使用。
- U5：用户指定 GitHub 地址，要求记录架构、PRD、ERD、规格书、更新记录、需求文档和当前系统真相。

优先级 P0 表示多人试用前必须满足；P1 表示完整迁移交付必须满足。优先级及具体实现策略是本轮建议，需求本身来自上述来源。

## 补充设计要求

以下是为满足目标提出的方案，尚不视为新增已确认功能：

- 个人草稿恢复、重复提交保护、回收站。
- 正常结案与中途终止分别记录结案类型。
- 报告固定数据快照；按用户保存页面偏好。
- 公网采用 HTTPS、服务端会话、限速、CSRF 防护及安全的内容渲染。
- 自动备份、异机副本、恢复演练以及按版本发布。

## 暂未定量的约束

正式项目数量、历史长度、导入文件体积、附件需求、数据增长速度、公司网络时延、可接受停机和数据丢失窗口尚未确认。性能指标见 SPEC-012，均为候选目标。

多租户、复杂权限分级、审批流、AI 自动决策、消息外发、外部系统自动同步尚无明确需求。不得以实现方便为由引入，也不得以缺少这些功能为由阻碍四人版本。
