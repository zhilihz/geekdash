# 需求清单

版本：D0.25；日期：2026-09-30。本文登记目标，不宣称服务器版已实现。

## 来源

- U1：用户提供 AIGeekDashCX.zip，要求找最新版本，讨论四人使用、速度、身份验证、状态记录、常驻 MySQL 和服务器架构。
- U2：用户明确四人均为管理员，权限相同；状态包括登录、页面筛选和位置、项目进度、修改历史。
- U3：用户指定使用 tccli 可访问的新加坡服务器测试；后续明确测试先走公网。
- U4：用户要求讨论 Redis 排队、判定和运行问题、深模块、有效测试、长期维护、更新推送时机和系统使用。
- U5：用户指定 GitHub 地址，要求记录架构、PRD、ERD、规格书、更新记录、需求文档和当前系统真相。
- U6：用户提供真实备份，要求反推字段关系、支持信息和阶段纠错，并在完整说明规则后由用户决定自动化。
- U7：用户确定五点技术路线；要求仅在实际写代码时默认使用 ponytail，AGENTS 明确文档职责；docs 内按类别建目录，暂无内容只留目录，并建立未完成任务交接。

优先级 P0 表示多人试用前必须满足；P1 表示完整迁移交付必须满足。优先级及具体实现策略是本轮建议，需求本身来自上述来源。

- U8：用户要求全部业务修改点击保存；全部项目可见，按自选负责范围编辑，录入者自动负责，允许自行加入/退出及多人负责；显示编辑者但不显示内容；固定详情版本，他人保存后保留文字供复制并重新进入；真实备份覆盖所有数据。

- U9：2026-09-30 用户确认检查整块规则，并要求独立卡片批量审查，有误才纠正、正确项选择后批量保存；明确先审查再写正式数据。

## 补充设计要求

以下是为满足目标提出的方案，尚不视为新增已确认功能：

- 个人草稿恢复、重复提交保护、回收站。
- 报告固定数据快照；按用户保存页面偏好。
- 公网采用 HTTPS、服务端会话、限速、CSRF 防护及安全的内容渲染。
- 自动备份、异机副本、恢复演练以及按版本发布。

## 暂未定量的约束

已收到真实导出样本，规模核查见系统真相。样本是否全量、附件需求、增长速度、公司网络时延、可接受停机和数据丢失窗口尚未确认。性能指标见 SPEC-012，均为候选目标。

多租户、复杂权限分级、审批流、AI 自动决策、消息外发、外部系统自动同步尚无明确需求。不得以实现方便为由引入，也不得以缺少这些功能为由阻碍四人版本。
