# 产品需求文档（PRD）

版本：D0.25；日期：2026-09-30；状态：服务器版讨论稿。

## 1. 产品目标

让公司 4 位管理员在同一份数据上管理智能硬件及软硬件协同项目，快速掌握进展、风险和下一步；每次操作有可靠保存、身份归属和可恢复入口。

需求编号及验收映射以[需求清单](../requirements/requirements.md)为准；本文只描述用户场景与体验。准确的校验和状态联动以[规格书](../specifications/specification.md)为唯一规则正文；未决项在[决策](../decisions/decisions.md)确认，本文不重复维护实现状态。

## 2. 使用者与使用环境

- 首批 4 位业务使用者，另设一个专用维护管理员账号（DEC-045）；全部项目可查看、搜索，项目编辑依据本人负责范围，见 SPEC-014。
- 账号代表实际操作身份；工程师资料库可以包含更多人员，二者不能强制一一对应。
- 测试环境先通过公网访问新加坡服务器；目标入口为 HTTPS。
- 原版以桌面 Chromium 浏览器为主。其他浏览器和移动端的正式支持范围待确认。
- 测试页面显著显示“测试环境”和实际运行版本。

## 3. 产品范围

保留原版六个页面所承载的能力：主看板与驾驶舱、项目详情、基础资料、状态纪要、芯片统计、系统设置；保留会议、流程图、导入导出、量产维护和多行状态描述。

首版保留现有页面和操作习惯，逐页接入 API；是否合并单页应用由实际切页体验决定。迁移需有功能清单和前后对照。

服务器版新增的基础能力是认证、共享持久化、并发保护、服务端历史、个人工作状态恢复、部署运维。草稿自动保存、回收站和报告快照属于建议方案，详见[决策](../decisions/decisions.md)。

## 4. 关键用户流程

### 4.1 登录并恢复工作

输入账号凭据 → 服务器认证 → 载入共享项目摘要 → 恢复本账号视图与筛选 → 后台校验缓存版本。

过期会话跳转登录；未提交输入提供恢复提示。退出后清理本设备的敏感业务缓存，下一账号不得看到前一账号的草稿。

登录后查看看板时，卡片、顶部数量、分布图和重点项目列表同时响应当前范围、筛选和搜索。使用者可明确切换“全部项目”范围；优先级与准确排序规则见 SPEC-018。

### 4.2 新建及启动项目

输入名称及已知客户、计划资料 → 点击保存 → 返回项目 ID、版本和创建记录，本登录账号自动负责该项目 → 在看板检索并进入详情。原业务人员字段与系统负责范围分开呈现。

新建后项目显示提案中、S1 待开始。负责人手动开始并完成 S1 后，另行确认日期、保存启动项目；S2 仍需手动开始。界面明确提示尚未满足的启动条件，具体校验见 SPEC-003。

### 4.3 日常跟踪

查看项目 → 核对本人负责范围 → 进入编辑并显示编辑者名单 → 修改信息 → 点击保存 → 核对服务端结果。未负责项目只读，可在负责范围设置中自行加入并保存后重新进入。

详情保持进入时版本；他人保存后显示“项目已被他人更新，请重新进入项目”，禁用旧版保存，保留文字供复制。“重新进入项目”载入最新数据，不自动带入旧输入。准确规则见 SPEC-002/014/015。

阶段推进时，负责人保存当前阶段完成后，下一阶段显示“待开始”；实际启动时选择“开始”并保存，才显示“进行中”。等待期间仍能看清下一步是哪一阶段。状态及校验统一见 SPEC-003，不能用填写日期代替开始动作。

长文本编辑保留换行。检查结论选择后点击“保存检查”，能查看检查人、时间和检查后更新提示；完整已确认口径见 SPEC-005。风险等自身处理仍待 Q-012。

填错信息或选错阶段时，使用者必须有纠正入口，能核对修改前后内容、看到保存结果并查到历史。阶段纠错按 SPEC-003 已确认规则显示影响并保存；其他对象见 SPEC-005。真实返工选择“回退”后显示目标阶段栏，填写原因、核对影响并点击“保存回退”。保存后目标阶段显示“待开始”，实际重新开工时另行开始并保存；历史中可查看原完成记录和每次回退原因。准确联动见 SPEC-003，不增加独立返工流程。

### 4.3.1 批量导入审查

用户上传后从独立“批量导入审查”入口进入批次，用卡片查看内容及问题。有误时打开纠正并保存待审修正；正确项勾选后点击“保存所选审查（数量）”，核对拟写入结果并明确提交。未处理项继续留在该批次，可分次接续；入库成功后可打开正式项目。已有项目卡片提供当前值与导入值对照，过期提示引导重新核对。待审项不参与正式看板和统计；首次入库卡片其他人可查看，上传者才有纠正和提交入口；保存入库后该账号自动负责，其他人可自行加入。更新已有项目仍按负责范围呈现操作。批量结果明确列出成功与待处理项，冲突项有重新核对入口；准确契约与剩余待决见 SPEC-009。

最后一位负责人选择退出时，提示先由其他人加入并保存；随后再退出。被拒绝的退出不改变当前负责关系。完整规则见 SPEC-014。

### 4.4 计划调整与逾期

用户可查看当前计划、原始计划和调整历史。选择调整计划时核对新日期与原因，点击保存；只补充说明使用独立入口，保存后仍能看到原有效计划。原始日期填错有纠错入口，变更影响保存前可核对，精确规则见 SPEC-004。

页面明确区分“当前超期”“曾改期”和“人工标记延期”；今日到期、计划未定、项目暂缓均有清楚提示。所有页面、筛选及导出按 SPEC-004 的同一口径展示，报告注明截至日期。结案后显示历史结果，重新打开后继续核对现行计划。

### 4.5 暂缓、结案与量产维护

使用者从详情执行暂缓、恢复、结案或维护操作，提交前看清将产生的影响，提交后可从看板和历史核对结果。暂缓期间可改信息及纠错，推进与返工需先恢复；界面同时显示暂缓标识和停留阶段。准确状态转换见 SPEC-003。

结案时选择正常完成或中途终止，核对遗留事项并保存，页面保留真实阶段进度。继续阶段工作前填写原因并重新打开；需要返工再选择回退目标。S7 阶段与结案后维护标识分别展示和操作，完整规则见 SPEC-003。

### 4.6 会议与输出

选择项目范围和字段 → 查看汇总 → 记录会议内容或生成报告 → 下载或后续汇报使用。

建议报告记录项目范围、生成时间和数据版本；生成期间的其他修改不混入同一份快照。导出失败给出错误和重试入口。原版可编辑单文件导出如何回流服务器数据待迁移讨论，不能默认为自动同步。

## 5. 交互状态

| 状态 | 用户可见信息 | 可执行动作 |
|---|---|---|
| 草稿 | 尚未提交，显示恢复来源和时间 | 继续编辑、提交、放弃 |
| 提交中 | 正在保存 | 避免重复点击，可保留输入 |
| 已保存 | 服务端确认时间和最新版本 | 继续工作 |
| 只读 | 本人未负责此项目 | 查看、搜索；可到负责范围设置中加入本人 |
| 他人正在编辑 | 显示编辑者姓名，不显示输入 | 保持固定业务视图，按版本规则编辑 |
| 版本过期 | 项目已被他人更新，请重新进入项目 | 禁用保存；复制未保存文字，再重新进入 |
| 保存失败 | 明确原因；不显示成功 | 修正或重试 |
| 网络不可用 | 离线/连接中，业务未确认提交 | 保留草稿，恢复后确认版本 |
| 后台任务 | 排队、处理中、成功或失败 | 查看结果、失败原因和可用重试 |

任何保存成功提示均须等待服务器提交确认。缓存显示要能表明正在同步，不能掩盖陈旧数据。

## 6. 数据保护及管理员能力

同为管理员不意味着可以在界面内无痕删除审计。账号管理、业务编辑、导入、删除恢复和备份操作都要记录身份。

共享资料、公共业务设置、账号启用/停用及维护账号换任由唯一维护管理员管理，其他账号可查看；项目负责范围仍按原已确认规则。维护页改名前展示引用影响；已引用资料使用停用入口。检查截止设置只选每周星期几，无需填写具体日期或时分；保存前显示“本周立即生效，以后每周沿用”，保存后刷新本周检查状态，已保存检查保留，准确规则见 SPEC-005/019。账号停用先完成项目交接，准确前置见 SPEC-001。处理人停用后，未完成导入批次提供填写原因、保存接管及重新核对入口，页面保留原上传身份和历次接管信息；行为见 SPEC-009。

共享业务资料与个人偏好分开。应用账号仅拥有本项目数据库所需权限，不能使用数据库 root 账号运行。

## 7. 成功标准

四账号能完成“真实输入 → 实际操作 → 持久提交 → 新请求回读 → 第二账号查看 → 报告消费”。并发、断网、重启、迁移及恢复有可验证行为。

性能候选指标、测量条件和通过标准见 SPEC-012；没有代表性数据和公司网络测量前，不承诺秒开或固定延迟。
